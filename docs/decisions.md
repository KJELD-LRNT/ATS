# Sponsor decisions

Product decisions taken after the MVP plan (`docs/mvp-plan.md`). Each one is enforced by the tests named below.

| # | Date | Decision | Where enforced |
| --- | --- | --- | --- |
| D1 | 2026-10-26 | **Every committed loan correction sends mail, including due-date-only corrections.** Recipients are the previous holder, the corrected holder and IT, deduplicated. Holders who can't be mailed are recorded as skipped and IT is still notified. | `CorrectionService.CommitAsync`; test `CorrectionServiceTests.Correction_for_the_same_holder_notifies_holder_once_plus_it` |
| D2 | 2026-10-26 | **The audit log is visible to IT only.** App admins and managers cannot read it, and nobody can edit or delete it. | `/Audit` (`Policies.ItOnly`), `AuditQueryService` (`EnsureIt`); tests in `tests/AssetTracker.Tests/Admin/AuditTests.cs` |
| D3 | 2026-10-26 | **A stale or long-stopped worker reports `Degraded`, not `Unhealthy`,** on `/health/ready`. Only a worker that has never written a heartbeat is `Unhealthy`. Monitoring should alert on `worker` being `Degraded` (see `docs/runbook.md`). | `WorkerHealthCheck` (`src/AssetTracker.Web/Health/ReadinessChecks.cs`); test `HealthEndpointTests.Worker_heartbeat_goes_stale_after_missed_intervals` |
| D4 | 2026-10-26 | **An item is overdue from the start of its due date** (`siteToday >= DueDate`), in the local calendar of the loan's site (tagged loan: the asset's current site; pool loan: the pool's site; site timezone, else `Clock:TimeZoneId`). Days overdue = days past the due date (0 = "due today"). Reminders are queued per site once its local time reaches `Notifications:ReminderTimeOfDay`, one per loan, site-local day and recipient. | `OverduePolicy`, `SiteCalendar`, `OverdueReminderService`; tests `ReminderScheduleTests.Overdue_starts_on_the_due_date`, `OverdueReminderTests` (`Sites_in_different_timezones_are_reminded_at_their_own_local_time`, `Dst_transition_day_produces_exactly_one_reminder_per_recipient`), `ReportTests.Overdue_report_follows_overdue_policy_in_each_sites_timezone` |
| D5 | 2026-10-26 | **Mail includes asset tag and phone number; default on.** Admins can turn the phone number off on Admin → Settings (`Notifications:IncludePhoneNumberInMail`). | `NotificationOptions.IncludePhoneNumberInMail` (default `true`); tests `NotificationServiceTests.Phone_number_is_included_by_default_per_decision_d5`, `ReminderScheduleTests.Options_bind_from_configuration` |
| D6 | 2026-10-26 | **A failed or rejected directory sync mails IT once.** One `SystemAlert` outbox row per run (dedupe `sync-alert:{runId}`) with run id, status, counts and a sanitized error/issue summary (no stack traces), saved with the run's completion; `Skipped` with a reason when the IT mailbox is not configured. | `DirectorySyncService.FinishAsync`, `NotificationService.QueueSystemAlertAsync`; tests `SponsorDecisionSyncTests.D6_*` |
| D7 | 2026-10-26 | **IT can view directory sync history and issues, read-only.** Only app admins see and can use "Run sync now" (an IT POST is 403). | `/Admin/Sync` (`Policies.ItOrAdmin`), `AdminService.ListSyncRunsAsync` / `RunSyncNowAsync`; test `AdminPagesTests.D7_it_can_view_sync_history_read_only_but_only_admins_can_run_a_sync` |
| D8 | 2026-10-26 | **A person whose AD site maps to no site can still be checked out to** (synced without a site, reported as `unmapped-site`). | `DirectorySyncService`, `LendingService.CheckoutAsync`; test `SponsorDecisionSyncTests.D8_person_with_an_unmapped_site_can_be_checked_out_to` |
| D9 | 2026-10-26 (reworded 2026-10-28) | **A manager grant is kept when the person turns inactive in a sync or loses the Manager role, but then has no effect;** it applies again if they return or get the role back. | `AccessScope.GetAsync` (Manager role + active person); test `SponsorDecisionSyncTests.D9_grant_is_kept_but_has_no_effect_after_the_manager_turns_inactive_or_loses_the_manager_role` |
| D10 | 2026-10-26 | **Return and correction mail to an inactive holder is recorded as `Skipped` with the reason, and IT is still notified** (the IT copy names the skipped holder). | `NotificationService.QueueLoanNotificationAsync`; test `SponsorDecisionTests.D10_return_and_correction_mail_to_an_inactive_holder_is_skipped_and_it_is_notified` |
| D11 | 2026-10-26 | **A correction supersedes the loan's latest event** (a return, or an earlier correction); the original events are never changed. | `CorrectionService`; test `SponsorDecisionTests.D11_correction_supersedes_the_loans_latest_event` |
| D12 | 2026-10-28 | **One built-in super admin account outside AD** (username `superadmin`, password only, exactly one). It runs the app without a domain account and is the failsafe for broken AD/mail settings, a lost admin role and a failed sync; it cannot help in a full domain outage (the app needs the gMSA to reach SQL Server). It gets the **Admin** role only (including Privacy), never IT, Manager or Facility; it is not in `RoleAssignments`, so no admin can remove it, and nobody can see or reset its password in the app. The first password (and resets, unlock, disable) comes from a **setup command on the server** (`deploy/Set-SuperAdmin.ps1` → a one-off scheduled task under the gMSA; the audit actor is the request file's owner); the app never ships with a default password. 5 failures lock it for 15 minutes; 10 attempts per IP per 15 minutes; sessions end after 30 minutes idle and 8 hours; sign-ins and lockouts are audited and mailed to IT. **All roles are managed in the app:** IT, Manager, Admin and Facility are given to people (picked from the directory snapshot) on Admin → System roles, together with the manager sites; no AD groups and no `Roles:*GroupSids` in the config file. A role needs an active person with a Windows account and counts only while the person is active; an admin cannot remove their own Admin role; the super admin may remove the last admin's and is then the only one who can give roles. Plan: `docs/plans/system-roles-and-super-admin.md`. | `SuperAdminService`, `SuperAdminSetupService`, `AppAuthentication`, `AppRoleClaimsTransformation`, `SuperAdminCommand`, `RoleAssignmentService`; tests in `tests/AssetTracker.Tests/Security/` (`SuperAdminSignInTests`, `SuperAdminLockoutTests`, `SuperAdminSetupCommandTests`, `RoleResolutionTests`) and `Admin/SystemRolesTests` |
