# Development guide

## Layout

| Project | Purpose |
| --- | --- |
| `src/AssetTracker.Core` | Domain entities, `AppDbContext` (provider-agnostic), application services, access scope, audit writer, adapter interfaces (`IClock`, `IDirectorySource`, `IMailRelay`). |
| `src/AssetTracker.Infrastructure` | SQL Server registration, EF migrations, production adapters (AD `DirectorySearcher`, SMTP relay, system clock), the background jobs (`Jobs/`, hosted by the worker) and the local demo mode adapters (`Demo/`). |
| `src/AssetTracker.Web` | ASP.NET Core Razor Pages on IIS, Windows Authentication, AD-group → app-role mapping, authorization policies. |
| `src/AssetTracker.Worker` | Windows Service hosting the background jobs from `Infrastructure/Jobs` (AD sync, mail outbox sender, per-site overdue reminders, heartbeat). |
| `tests/AssetTracker.Tests` | Integration-first tests: `AppFactory` runs the real app against a real relational DB with simulated Windows principals and fake AD/relay. |

## Running locally

```bash
dotnet test                               # SQLite temp-file DB per test class
ATS_TEST_SQLSERVER="Server=...;User Id=...;Password=...;TrustServerCertificate=True" dotnet test   # real SQL Server
```

The production app requires `ConnectionStrings:AssetTracker`, `Roles:*GroupSids` and `DataProtection:KeyPath` in its config file, and `Clock:TimeZoneId` (plus the AD and mail settings) on Admin → Settings. **No production values are defaulted**: they come from Stage 0 (see issue #2).

## Conventions

- **Authorization lives in services and queries, not just pages.** Every read path goes through `AccessScope` (`VisibleAssetsAsync`, `VisiblePoolsAsync`, `VisibleLoansAsync`, `EnsureCanReadSiteAsync`). Every mutation calls `AccessScope.EnsureIt()` (or `EnsureAdmin()` for settings/grants). Page policies (`Policies.ItOnly` / `InventoryRead` / `AdminOnly`) are a second layer.
- **Audit in the same transaction.** Call `AuditWriter.Record(...)` before `SaveChangesAsync()`; never write audit in a separate save.
- **Errors.** Throw `DomainException` (400), `ConflictException` (409) or `AccessDeniedException` (rendered as 404). Pages get this mapping via `DomainExceptionFilter`.
- **Concurrency.** Never read-modify-write a pool balance. Use a conditional atomic update, e.g. `ExecuteUpdateAsync(... WHERE Available >= @q)`, and check the affected row count. A tagged asset's single open loan is enforced by the `UX_Loans_OpenAsset` unique index; translate its `DbUpdateException` into a `ConflictException`.
- **Time (WP4.2).** Store and compare instants as UTC `DateTimeOffset` via `IClock.UtcNow` (return/correction "not in the future" checks stay instant-based). `IClock` deliberately has no "local today": calendar days are per site. Use `SiteCalendar` (Core/Time): `TodayForAsync(siteId)`, `TodayForAsync(loan)` (tagged loan → the asset's **current** site, pool loan → the pool's site), `LocalTimeForAsync(siteId)`, `AllSitesAsync()` and `OverduePredicateAsync()` for queries. A site's zone is `Site.TimeZoneId` (IANA or Windows id), else the default `Clock:TimeZoneId` (`ClockOptions`, read via `IOptionsMonitor`); neither set ⇒ `InvalidOperationException`. `SiteCalendar.DefaultToday` is only for things that belong to no site (export file names). Due dates are `DateOnly` in the loan's site calendar and must be ≥ that site's today at checkout.
- **Overdue rule (D4).** `OverduePolicy` is the only definition: overdue when `siteToday >= DueDate` (from the start of the due date); `DaysOverdue = siteToday − DueDate` (0 on the due date, shown as "due today"). Reports, the loans list filter, the reports summary and reminders all use it through `SiteCalendar`. Tests: the default zone is UTC (`AppFactory`), `FakeClock.UtcToday` is every default-zone site's today; give a test site a `TimeZoneId` to test another zone.
- **Migrations.** Feature branches change the model freely; migrations are regenerated by the integrator (`dotnet ef migrations add <Name> -p src/AssetTracker.Infrastructure -s src/AssetTracker.Infrastructure -o Data/Migrations`). CI fails if the model and migrations differ. **Exception:** `ZoneRename` is hand-written (renames instead of the scaffolded drop and create, which would lose the zones); it was made with `migrations add` and its Up/Down replaced, so do not regenerate it. It is tested by `ZoneRenameMigrationTests` (SQL Server only, `[SqlServerFact]`).
- **Tests.** Prefer `AppFactory` integration tests (HTTP via `CreateClientAs(TestUser.X)` or services via `RunAsAsync(TestUser.X, sp => ...)`). Use fictional fixture data from `Seed`. Use unique site keys/tags per test, because each test class shares one database.
- **Service registration.** Add scoped services in `CoreServiceCollectionExtensions.AddAssetTrackerCore` and adapters in `InfrastructureServiceCollectionExtensions`.
- **Append-only ledgers.** `AppDbContext.SaveChanges*` throws `InvalidOperationException` if an `AuditEvent`, `LoanEvent` or `StockEvent` is modified or deleted through the change tracker. Never use `ExecuteUpdate`/`ExecuteDelete` on those sets (they bypass the guard). The one permitted update is linking a transfer pair: `StockEvent.CounterpartEventId` may be set once, from null.
- **Audit visibility: IT only (sponsor decision D2, `docs/decisions.md`).** `/Audit` (policy `ItOnly`) and `AuditQueryService` (`EnsureIt`) are read-only; there is no edit/delete path. Admins cannot read or alter audit by the admin role alone.

## Database-backed settings (WP4.1)

- **Where values come from.** `AppSettings` rows whose key is a configuration path in the `ActiveDirectory`, `DirectorySync`, `Mail`, `Notifications` or `Clock` section (`SettingCatalog.IsConfigKey`) are overlaid on the appsettings files by `DatabaseSettingsConfigurationProvider` (Infrastructure/Configuration), the **last** configuration source, so the database wins. Other keys (`Mail.ItMailbox`, `Worker.Heartbeat`, `Worker.Version`, and anything like `Roles:*` or `ConnectionStrings:*`) are never exposed as configuration. Options classes bind unchanged (`services.Configure<T>(config.GetSection(...))`).
- **How the provider reaches the database.** The provider is built with the configuration, before DI exists, so it never opens a connection itself. `DatabaseSettingsReloader` (singleton `ISettingsReloader`) reads the rows through a scoped `AppDbContext` — whatever the host registered: SQL Server in production, the test database under `AppFactory` — and calls `provider.Apply(rows)`, which swaps the data and fires the reload token only when something changed. Program.cs (web and worker) calls `LoadDatabaseSettingsAsync()` right after `Build()` (it also moves the source to the end if a later source was added, e.g. by `WebApplicationFactory`); `DatabaseSettingsRefreshService` reloads every `Settings:ReloadInterval` (30 s); `SettingsService` reloads after each save. A database error (unreachable, table not migrated yet) is logged once and the previous values stay; it never throws.
- **Consumers must read live values.** Singletons inject `IOptionsMonitor<T>` and read `CurrentValue` per use (`SmtpMailRelay`, `ActiveDirectorySource`, `DirectorySyncJob`, `OutboxSenderJob`, ...). For these five sections `IOptions<T>` is registered transient and resolves to the current value, so a scoped service that injects `IOptions<T>` sees changes on its next scope; a singleton that captures `IOptions<T>` would not.
- **Editing.** `SettingsService` (Core/Settings, admin only) validates a whole section (`SettingCatalog` holds keys, labels, kinds, defaults and validation; defaults must equal the options classes, pinned by `SettingsConfigurationTests.Catalog_defaults_match_the_option_class_defaults`), writes rows, audits each changed key as `setting.update` (`{before, after}`), then reloads. Empty value = remove the override. To make a new setting editable, add it to `SettingCatalog` (page and validation follow).
- **Secrets.** `Mail:Password` is stored as Data Protection ciphertext (`ISecretProtector`, purpose `AssetTracker.Settings.Secret.v1`) and exposed to configuration only as `Mail:PasswordProtected`; `SmtpMailRelay` decrypts at send time. It is write-only on the page and audited as `{secret: true, change: set|cleared}`. Web and worker share the key ring: `AddAssetTrackerDataProtection` sets the application name `AssetTracker` and persists keys to `DataProtection:KeyPath` (machine DPAPI on Windows); Testing uses an ephemeral key ring.
- **Test buttons.** *Test directory query* calls `DirectorySyncService.PreviewAsync` (same validation and safety checks as a run, no writes; audited `directory.preview`); *Send test email* calls `IMailRelay` directly (audited `mail.test`).

## Directory sync (WP1.4)

`DirectorySyncService` (Core) runs a full sync from `IDirectorySource`; the worker's `DirectorySyncJob` schedules it and admins can rerun it from `/Admin/Sync`. IT can view `/Admin/Sync` read-only (policy `ItOrAdmin`, D7); the rerun POST is admin-only (403 otherwise). A `Failed` or `Rejected` run stages one `SystemAlert` mail to the IT mailbox (`sync-alert:{runId}`, `NotificationService.QueueSystemAlertAsync`) in the same save as the run (D6). The production adapter `ActiveDirectorySource` (Infrastructure, Windows only) uses a paged `DirectorySearcher` (subtree, `PageSize` 500).

These are edited on Admin → Settings (see above).

| Setting | Default | Notes |
| --- | --- | --- |
| `DirectorySync:Interval` | none | Worker schedule (e.g. `01:00:00`), re-read at least every minute. Unset ⇒ the worker logs an error and does not sync until it is set; IT sees the stale warning. |
| `DirectorySync:MaxDropFraction` | `0.2` | **Safety check, on by default.** A run that would deactivate more than 20% of currently active people (absent or disabled) is `Rejected` and not applied. |
| `DirectorySync:MinimumExpectedCount` | `0` (off) | Absolute floor on valid entries; set from the client's directory size in Stage 0. A run with zero valid entries is always rejected. |
| `DirectorySync:StaleAfter` | `1.00:00:00` | Placeholder until the sync frequency is agreed; drives the IT stale banner and `GetStatusAsync()`. |
| `ActiveDirectory:SearchRoot` | none | LDAP path of the in-scope OU. Required. |
| `ActiveDirectory:SiteAttribute` | none | Attribute holding the designated site. Required. |
| `ActiveDirectory:Filter`, `IdAttribute`, `PageSize`, `*Attribute` | standard AD names | `objectGUID` id, `sAMAccountName`, `displayName`, `title`, `mail`, `objectSid`, `userAccountControl` (bit 0x2 = disabled; missing ⇒ treated as disabled). |

Rules: people are keyed on the directory id (rename updates the same row) and never deleted; absent or disabled ⇒ `IsActive = false`. Entries without id/username, or sharing an id or SID with another entry, are quarantined (skipped and reported; an existing person with that id is left untouched). A site value that matches no `Site.DirectoryValue` (case-insensitive) is **not** quarantined: the person is synced with no site and an `unmapped-site` issue is recorded. A failed fetch (`Failed`) or a safety-check rejection (`Rejected`) leaves the previous snapshot unchanged. Each run writes one `directory.sync` audit event.

## Operations, security headers and privacy (WP3.2)

- **Health:** `/health` (liveness, no checks) and `/health/ready` (database, directory sync, mail outbox, worker heartbeat; `Web/Health/ReadinessChecks.cs`). Both anonymous; the JSON writer emits only fixed descriptions. Thresholds: `Ops:*` (`OpsOptions`). See `docs/runbook.md` §8.
- **Worker heartbeat:** `WorkerHeartbeatJob` upserts `AppSetting` rows `Worker.Heartbeat` / `Worker.Version` (`UpdatedBy = system:worker`) every `Worker:HeartbeatInterval`; `OpsStatusService` reads them. The IT dashboard is `/Ops`.
- **Security headers:** `Web/Security/SecurityHeaders.cs` sets CSP (`script-src 'self'; style-src 'self'`, no inline), `X-Frame-Options: DENY`, `nosniff`, `Referrer-Policy: no-referrer`, and `Cache-Control: no-store` on every non-static response. **Do not add inline `<script>`, `<style>`, `style=""` or `on*=` handlers**; use `wwwroot/js/site.js` (e.g. `data-confirm="..."` on a form) and `site.css`.
- **Privacy:** `PrivacyService.AnonymizePersonAsync` (admin, audited `privacy.anonymize`) and `Person.IsAnonymized`, which `DirectorySyncService` never updates. New code that stores holder personal data in a *mutable* table must be added to the anonymization scrub; never put names/emails into append-only ledgers. See `docs/privacy-and-retention.md`.

## Asset catalog: types, custom fields, vendors, models, tag generator

Admins define what can be tracked; there is no hard-coded asset type any more (`Core/Domain/AssetType.cs`, `AssetField.cs`, `Vendor.cs`; service `Core/Catalog/CatalogService`; pages `Admin/Types`, `Admin/TypeEdit`, `Admin/Vendors`, `Admin/Models`).

- **Types** (`AssetType`, table `AssetTypes`): `Mode` is `Tagged` (individual asset with a tag) or `Pooled` (a site quantity `Pool`). A tagged type switches the standard fields of its form on or off (`UsesModel`, `UsesDescription`, `UsesSerialNumber`, `UsesCondition`); values for a field the type does not use are ignored by `AssetService`. The mode cannot change once the type has assets, pools, fields or models. Types, fields, vendors and models are never deleted, only deactivated (`IsActive`), because assets point at them. `Asset.Type`/`Pool.Type` is the entity: `ToString()` is its name, so `@asset.Type` and mail text still work, but queries must `Include` it.
- **Custom fields** (`AssetFieldDefinition`, `AssetFieldValue`): kinds `Text`, `Number`, `Date`, `Choice` (options one per line), `PhoneNumber` (E.164) and `Imei` (15 digits, Luhn). A field has `IsRequired`, `IsUnique`, `IsSensitive` (IT only) and `MaxValues` (1-5; the default Phone type has two IMEIs for dual-SIM phones). `FieldValueRules` normalizes and validates; `AssetService` stores the values in `AssetFieldValues` (position = order). A field absent from `EditAssetInput.Fields` keeps its values; present = replaced (a blank list clears it). The Edit page therefore posts every active field explicitly.
- **Uniqueness** is a filtered unique index on `AssetFieldValue.UniqueKey` (`[UniqueKey] IS NOT NULL`). The key is set for unique fields while the asset is not retired and cleared on retirement (so a number can be reused). Phone numbers and IMEIs are unique across all fields of that kind (`PhoneNumber:+31…`), other unique fields per field. Kind, uniqueness and a lower `MaxValues` cannot change once an asset has a value for the field.
- **Sensitive fields.** `AccessScope.CanSeeSensitiveFields` (IT only). `AssetService` loads, searches and reports without sensitive values for others, the details page hides the field, mail never includes them and the audit trail records `(sensitive)` instead of the value.
- **Vendors and models.** A model belongs to one vendor and one tagged type. An asset stores `VendorId` and `ModelId` (`Title` = "Vendor Model"); a model implies its vendor and must match the asset's type and vendor, and an inactive model/vendor can only stay on assets that already have it. `Description` is a separate free-text property.
- **Mail (D5)** takes the phone number from the first non-sensitive `PhoneNumber` field; reports (`InventoryAssetRow`) list the `PhoneNumber` and `Imei` field values.
- **Tag generator** (`Inventory/TagPattern`, `TagGenerator`). `AssetType.TagPattern` is a pattern such as `{SITE}D{000}OMA`: `{SITE}` is `Site.TagCode` (unique per site, set under Admin → Sites), `{000}` the counter (zeros = minimum digits), letters, digits, `-`, `_` and `.` are literal. The counter (`TagCounter`, last number per type and site) is claimed with a compare-and-set update inside the transaction that inserts the asset, so a failed create does not use a number; numbers whose tag already exists (typed by hand) are skipped. The new-asset form previews the next tag and creating with an empty tag generates it; a typed tag overrides it. A type with no pattern, or a site with no tag code when the pattern needs one, asks for a typed tag.
- **Defaults and migration.** `BuiltIn` holds the ids of the types and fields every installation starts with (Desktop, Laptop, Phone, Phone number, Peripheral, Webcam, Headset; phone number fields: provider, SIM type, SIM status, SIM number, PUC). The `AssetCatalog` migration inserts them (the ids equal the old `AssetType` enum values, so existing rows keep their type) and moves `IndividualAssets.Imei`/`PhoneNumber` into `AssetFieldValues`; `CatalogDefaults.EnsureAsync` does the same for databases created from the model (tests, demo). Keep the two in step. The migration's data conversion has not been run against a populated SQL Server by CI; try it on a copy of production data first.
- **Checkout finders.** Both fields of `Loans/Checkout` are ARIA comboboxes built by `createCombo` in `wwwroot/js/site.js`; each only enhances the plain GET form (*Find*), which keeps working without JavaScript.
  - *Who receives it?* `?handler=People&q=` (IT only, at least 2 characters, at most 8 people who can receive a loan) returns JSON with each person's site and fills the hidden `holderId`.
  - *What is being lent?* `?handler=Items&q=&type=&site=` returns assets **and** quantity pools in one list (`LendingService.SearchItemsAsync`, IT only, at most 10). The text is matched like the asset list (`AssetService.MatchingTerm`: tag, vendor/model, serial number, description, any custom field value, phone numbers/IMEIs by digits when the text looks like a number); pools by SKU, description and type name. Retired assets are never offered. Items that cannot be lent (checked out with the holder's name, unavailable, a pool with none left) are listed after those that can, greyed and not selectable; an exact tag or SKU always comes first. With an empty text it lists what is available (browse; the finder opens on focus). Picking fills `assetId`/`poolId` (disabled until picked, so without JavaScript only the text is sent); editing the text clears the pick. Picking a person sets the site filter to theirs unless the site was chosen by hand.
  - Server side (no JavaScript, or Enter on typed text): `CheckoutModel.ResolveItemAsync` takes a picked id, else an exact tag, else the text: exactly one match is selected, several are listed as links (`Matches`), none is an error. The quantity of a pool is set in the confirm step.

- **Overview and tiles.** The home page (`Pages/Index`) is made of tiles listed in `Core/Overview/OverviewTiles.cs` (`OverviewTileKeys`, `TileDefinition`: key, title, allowed roles, default roles). `OverviewTileService` stores which roles see each tile as `AppSettings` rows `Overview.Tile.{key}` (value `It, Manager` or `None`; no row = the default). A tile can never be given to a role outside its `AllowedRoles` ("Needs attention" shows mail status, so it is IT only), the page shows a tile when any of the user's roles has it, and only admins change it (Admin → Overview tiles; audited as `overview.tiles` / `overview.tiles.reset`). The page loads only the data of tiles that are shown. Each count is a link to the list behind it (`?siteId=` is passed on), and `?site=` narrows every tile to one site the principal may read (an unreadable site is ignored). `OverviewService.GetAttentionAsync` counts the "needs attention" items (open loans held by inactive people, unavailable assets, pools below minimum, failed mails); `ReportService.DueSoonAsync` lists loans due in the next 7 days; `?handler=Find` backs the find box (IT only, JSON of assets, pools and people) and is wired up in `site.js` (`[data-find-lookup]`; Enter on one hit opens it, an exact checked-out tag goes to its return page).
- **Pool minimum stock.** `Pool.MinimumStock` (nullable; migration `PoolMinimumStock`) is set on *Pools → New pool* or the pool page (`PoolService.SetMinimumAsync`, IT only, audited as `pool.minimum`). A pool is *below minimum* when `Available < MinimumStock`; the pool list has a "Below minimum" filter and badge, and the overview's stock tile sorts those first.

## Workplace: floor plans, workspots and zones

An extra module for IT, facility and operations (`Core/Workplace`, `Core/Domain/Workplace.cs`, pages `Pages/Workplace/*`, migrations `Workplace`, `WorkspotAssignments`, `FloorPlanDesks` and `ZoneRename`): import a floor plan (SVG), find a seat, room, zone, person or asset on the map, group seats into zones, drag people, desktops and screens onto desks, see free desks and what to check, and print the map (or a part of it) to PDF with the browser.

- **Roles.** `AppRoles.Facility` is **not** an AD group: an admin gives it to a person under Admin → *System roles* (`RoleAssignmentService`, table `RoleAssignments`, audited as `role.assign` / `role.remove`). `AppRoleClaimsTransformation` adds it on every request, matching the person's SID, only while the person is active in the directory snapshot (it adds to the AD roles: IT + Facility is both). Facility opens the Workplace only; `AccessScope.GetAsync` (inventory, loans, reports) stays closed to it. `AccessScope.GetWorkplaceAsync` is what floors are read through: IT and facility all sites, managers their granted sites (read only, other sites are 404). Policies `WorkplaceRead` (IT, facility, manager) and `WorkplaceEdit` (IT, facility).
- **Import** (`FloorplanImporter`, `FloorplanCss`). The drawing is embedded in a page with a strict CSP, so it is **sanitised on import** and stored sanitised (`Floor.Svg`, `Floor.Css`): only drawing elements and presentation attributes survive (no script, `a`, `image`, `use`, `foreignObject`, animation, event handlers or external references; DOCTYPE is ignored and entities are never expanded); `style` attributes become presentation attributes; the `<style>` element is reduced to a whitelist of properties, scoped to `.floorplan` and its class names are prefixed `fp-` (so the drawing cannot restyle the app and the reverse), and served from `Floor?handler=Css` (the CSP allows styles from the app itself). A `url(#id)` pattern fill in a rule for one class is moved to a `fill` attribute on those elements, because a separate stylesheet cannot refer to the pattern in the page. Limit 5 MB.
- **Workspots.** A workspot is a **seat**: every element with `data-kind="seat"` (the format of the facility team's renderer, with `data-kind`/`data-id`/`data-name`/`data-type`/`data-parent` on rooms, tables and seats) becomes a `Workspot` with the room and table it sits in. **A seat has no name of its own in the UI**: `Workspot.Label` (the seat's `data-id`, or the element id of a marked shape, unique per floor) is internal and only used for ordering and the audit log; people know a desk by who sits there, its desktop, and its zone and room (`Workspot.Place`: "Finance", "Sales · Open space"), which is what the panel, tooltips, flags, free-desk lists, messages, search results, the asset page and the printed desk list show. For a plain drawing every shape gets an id (`fp-e1`, …) and the editor marks the seats on the map (*Mark as workspots*). A seat's table and room are the ones it is drawn in, else the ones its `data-parent` (or its table's) names, else the smallest room whose outline holds its centre. Floors are archived, never deleted.
- **Drawings change** (`SeatMatcher`, `FloorService.ReplaceDrawingAsync`). The drawings are not final, so nothing depends on how one is made. *Replace drawing* finds every seat again: by element id; else by the drawing's seat id (`data-id`, a re-made drawing with other element ids); else by position, the nearest candidate within half the usual distance between seats, measured both in drawing units and relative to the viewBox (a re-scaled drawing) and taking whichever finds more. An automatic id (`fp-e12`) only counts when the shape is still in about the same place, so a seat marked on a plain drawing follows its shape when a new export shifts the numbering. A seat found again keeps its id, zone, placements and desk setting (its room, table and seat id are read again; a seat whose room changed type becomes a desk or not by the new type unless something is placed at it). New seats are added; seats not found are switched off (`IsActive`, never deleted, their zone kept for when they come back) and whoever is placed there is flagged (`ImportResult.Orphaned`, in the message). The result also counts `Moved` (found under a new id or place).
- **Geometry** (`SvgGeometry`). Every measurement on the server (markers, which side of its table a seat is on, zone outlines, the seats of a printed area, rooms by position, matching by position) uses the box of an element in the root's user space: rect, circle, ellipse, line, polygon, polyline, path (curves by their control points) and groups of them, under any `transform` (matrix, translate, scale, rotate, skew) on the element and its ancestors; `defs`, text and the like are left out. Sizes follow the drawing's own seats (`unit` = median seat size: outline padding, zone name size), not the viewBox. In the browser `userBox` (site.js) measures on screen and maps back, so zooming to a selection, printing it and the label threshold work with transforms too; a seat drawn as a group passes its state colours to its shapes (site.css).
- **Zones** (`FloorZone`, `ZoneService`). A cluster of seats on one floor with a name and one of 8 colours (`zc-0…7` in `site.css`); a seat is in at most one zone, so a **table can be split** between zones; rename, recolour, add, remove, delete are all audited and a zone is **display only** (no link to the directory or to loans). In the side panel one *Zone* box (`Floor?handler=SetZone`: an existing zone id, `new` with a name, or `none`) applies to whatever is selected: a whole table (click it), part of a table (Shift-click seats or Shift-drag) or a room. `FloorplanRenderer` draws a dashed outline per zone **per table** (seats without a table: per room) and the zone's name once per room, under the outline when those seats are on the far side of their table. Zones were called *teams* before: the audit log keeps the older `team.*` rows (entity `FloorTeam`, and `team.remove` against `Floor`) as they are and new rows use `zone.*` / `FloorZone`; the audit page shows old rows under the new name with the stored one muted, an action filter starting with `zone` also matches `team` (`zone*` finds both) and the entity filter lists one `FloorZone` entry for both (`AuditNames`).
- **Map** (`site.js`, "Workplace floor map"). The canvas fills the window below the top bar and the header (`sizeCanvas`, at least 480 px); the side panel is sticky and scrolls on its own. The view always has the canvas's shape, so nothing is cut off. *Fit* (and the first view) shows the **content box**: `FloorplanRenderer` writes `data-content="x y w h"` on the drawing, the box around its rooms, tables and seats plus 2.5% (`FloorplanRenderer.Content`), not the drawing's viewBox with its paper margins; a printed whole floor uses the same box. Floating controls in the canvas's top-right corner (`.wp-mapctl`: zoom level, in, out, *Fit*, *Select area*, *Full screen*); the search, *Zones*/*Names* and the print menu stay in the toolbar. *Full screen* is a class (`.wp.is-full`, not the Fullscreen API): the stage is fixed over the whole window and the panel comes back as an overlay on the right while something is selected (`has-selection`). Esc undoes one step per press: a search list closes itself (it handles the key), then print-area mode, search highlights, the selection, full screen. Double-click a room to zoom to it; the arrow keys move the map. Pan (drag), zoom (wheel, pinch, buttons, `+`/`-`/`0`), select (click a seat, Shift-click to add, click a table or room for its seats, Shift-drag or *Select area*), search (`WorkspotService.FindAsync`: rooms by name or number, zones, placed people and desktops, on every floor the principal may see; never seats by their drawing id; `Workplace?handler=Find`) and focus links (`Floor/{id}?focus=ws:ID[,ID…]|room:ID|zone:ID`; the old `team:ID` links still work). The selection only fills the hidden `ids` of the side-panel forms; the server does the changes and redirects with `focus` set to the changed seats, so they stay selected. Without JavaScript the map is a static picture.

- **Desks, desktops and screens** (`WorkspotAssignment`, `AssignmentService`, migrations `WorkspotAssignments` and `FloorPlanDesks`). Only three things are **placed** at a seat: one person, one desktop and any number of screens (`PlacementKind`). Which asset types are desktops or screens is set per type by an admin (`AssetType.WorkspotRole`, Admin → Asset types → *On floor plans*; built in: *Desktop* and *Screen*); other assets and pools are never placed. A seat is a **desk** (`Workspot.IsDesk`) unless its room type is canteen, meeting, support, core, workshop, kitchen or lounge; editors can switch it (*Seat settings → Make desk / Not a desk*). Only active desks on an active floor take placements. It records *where*, for planning: it is separate from loans and the floor plan does **not** check who an asset is loaned to. A person and an asset are in **one place at a time**: placing them elsewhere moves them (the old row is closed, kept as history); a second person or a second desktop at a desk is a `ConflictException` until released. Assets must belong to the floor's site; persons may come from any site. Retiring an asset or moving it to another site releases it (`AssignmentService.ReleaseAssetAsync`). The rules are filtered unique indexes (`UX_WorkspotAssignments_*`) plus `CK_WorkspotAssignment_Kind`. A seat with something placed cannot be switched off or made *not a desk*. Reading follows `GetWorkplaceAsync`; placing needs IT or facility; every change is audited (`assignment.assign`, `assignment.release`, `workspot.desk`, `workspot.not-desk`).
- **Flags and status** (`AssignmentService.StatusAsync`, partial `_FloorStatus`). Per floor: free desks, desks taken, desktops and screens placed, and **to check**: a person who left the directory (`person-left`), a person at a seat that is switched off or not a desk (`seat-disabled`), a person at a desk without a desktop, without a screen or without both (`missing`). Names are shown as they are in the directory (an anonymized person shows the pseudonym).
- **Seat state on the map** (`FloorplanRenderer`). The stored drawing gets per seat the state classes (`fp-free`, `fp-occ`, `fp-nodesk`, `fp-ws-off`, `fp-left`, `fp-flag`), icons (`<symbol>`s `fp-i-person/desktop/screen/warn` with `<use>`: person in the seat, desktop and screen badges beside it away from the table, a ring around a flagged seat) and a label with the person's name and the desktop tag (the server's label is the fallback without JavaScript; the seat carries the full texts as `data-person`/`data-desktop`). *Free desks* and *To check* in the status highlight those seats on the map.
- **Label engine** (`createLabelEngine` in `site.js`, used by the floor page and the print page). Labels are drawn in screen pixels (each label group is scaled so one unit is one pixel). Once per drawing every label gets a slot in drawing units along its row (up/down labels) or column: up to the neighbouring desks on that side, all of the gap when the neighbour has no label, half of it when it has one. When the zoom has changed by more than 4% (while zooming only big jumps; the rest when the zoom settles, `scheduleLabels`) the text is fitted again: the largest size between 12 px and `minPx` (10 px on screen; 7 pt × the sheet's scale on the print page), else a shorter form: names *Gabi Demoson* → *Gabi D.* → *GD*, tags without the site prefix (`data-tag-prefix`, `AMS-`). Widths are measured with a canvas once per text and font. Names are placed first (rows spread within their slots, then one by one from the top left, sliding along the row but always covering their own desk; labels in the way of one that does not fit step down a form and the pass runs again), then tags where they fit. Nothing may touch another label, a seat or the drawing's own text. What still does not fit becomes a **callout**: a numbered dark circle next to the desk, never hidden; numbers that would touch share one; a key lists them (*Numbers on the map* in the canvas corner; under the map on the print page). Zone names move above the labels or below their tables when a label is where they were, else they are left out. The engine only sets SVG attributes and `element.style` properties (CSP). `root.wpLabels().inspect()` shows its state in the console.
- **Drag and drop** (`site.js`, "Workplace floor map"). Editors get a palette of unplaced people, desktops and screens (`Floor?handler=Palette&kind=person|desktop|screen&q=`; without a search only the floor's site, with a search people of every site). Drag an entry (or an entry of the selected seat's panel, to move it) onto a seat, or select a desk and click an entry. The drop posts `handler=Assign` with `Accept: application/json` (409/400 with a message when refused), then swaps in `handler=Map` and `handler=Status` without reloading, keeping the zoom. Without JavaScript the forms still post and redirect.
- **Finding things.** `WorkspotService.FindAsync` also finds placed people (name, username) and assets (tag, description) and returns the seat (`Floor/{id}?focus=ws:ID`). `AssignmentService.SearchAsync` (editors) finds people, desktops and screens (`AssetService.MatchingTerm` **without** sensitive fields, so a facility user cannot find an asset by a PUC) with where each is now. The asset page shows where it is placed (`LocationOfAssetAsync`, only floors the principal may see).
- **Print / PDF** (`Pages/Workplace/Print`, `_PrintLayout`). The PDF is the browser's own *Print → Save as PDF*: the print page lays out page 1 (`.print-page`) with the map, the key to callout numbers (when there are any) and the legend, and on the next pages the list of desks **grouped by zone, then room** (person, desktop, screens, note; `PrintModel.Groups`), plain free desks (no desktop, screens or flag) as one line per room (*Sales: 12 free*). Paper: A4 landscape by default (`@page floorplan`, sheet 1047 px = 277 mm at 96 dpi); `paper=a3` adds `.print-sheet--a3`, which selects `@page floorplan-a3` (A3 landscape) and a 1512 px sheet (400 mm). The paper switch is a pair of links that keep the area and title; when the label engine needs callouts on A4 the page shows *This floor is easier to read on A3* (`data-a3-hint`), never switching by itself; Safari ignores named page sizes, so the hint tells Safari users to pick A3 in the dialog. While printing (`beforeprint`) the sheet is laid out at its paper width (`.is-printing`) and the labels are fitted again. A whole floor prints the content box; `area=x,y,w,h` (drawing coordinates) prints a section: the current view, the selected seats or an area dragged on the map (*Print / PDF* menu); `auto=true` opens the print dialog; `list=false` leaves out the list.

## Local demo mode (WP5.1)

`dotnet run --project src/AssetTracker.Web --launch-profile Demo` runs the whole app on one machine with fictional data; the user-facing guide is [`docs/testing-guide.md`](testing-guide.md).

- **Activation.** `Demo:Enabled=true` (`DemoOptions`, Infrastructure/Demo) is honoured only when `IHostEnvironment.IsDevelopment()`; in any other environment `DemoOptions.Resolve` throws at start-up. When off, nothing changes: Program.cs registers Negotiate as before and the `/Demo` pages get no route (`ConfigureDemoPages` clears their selectors, so they are 404).
- **What it swaps** (`AddDemoWeb` → `AddAssetTrackerDemo`, called after the production registrations): SQLite at `<Demo:DataDirectory>/demo.db` (`EnsureCreated()`, WAL; the migrations stay SQL Server only), `DemoClock` (real time + offset stored in the `Demo.ClockOffset` AppSetting; seeding pins it per async flow), `DemoDirectorySource` (fixed fictional directory), `PickupDirectoryMailRelay` (`.eml` files under `mail/`, read by `/Demo/Mailbox`), a plain key folder `keys/`, the background jobs hosted in the web process (`AddAssetTrackerBackgroundJobs`, shared with the worker), `DemoAuthenticationHandler` (emits Name/PrimarySid/GroupSid like Negotiate, from the `/Demo` role-switcher cookie) and `DemoCurrentUser` (seeding actor → HTTP user → `system:worker`). Demo configuration defaults (role group SIDs, short intervals, timezone) are an in-memory source added before the database settings overlay, so Admin → Settings still wins.
- **Floors.** AMS *Floor 1*, *Floor 2*, NYC *Floor 1* and the dense AMS *Floor 3* (`DemoFloorplans.Amsterdam3`: an open plan of twelve 8-seat tables in a 4 × 3 grid, `Room.Columns`), where 86 people (three with long names, `DemoDirectorySource.LongNameUsernames`), `DemoSeeder.DenseFloorDesktops` desktops (`AMS-DT-005` and up) and `DenseFloorScreens` screens are placed, to check crowded labels.
- **Seeding** (`DemoSeeder`) goes through the real services as an IT+admin actor, in time order with the clock pinned to past instants, so audit, ledgers and outbox are consistent; seeded mail is marked sent. It only runs on an empty database; **Reset demo data** (`DemoDataManager.ResetAsync`) empties every table and seeds again.
- **Tests:** `tests/AssetTracker.Tests/Demo/` (`DemoAppFactory` = Development + demo + temp folder, jobs off).
- Production code never references the demo types except through these Program.cs hooks, the layout's `DemoBanner` view component (renders nothing when demo is off) and the settings page note.

## UI style: "Midnight Command" (light and dark)

One stylesheet, `src/AssetTracker.Web/wwwroot/css/site.css`; view helpers in `Pages/Shared/Ui.cs` (status pills, inline SVG icons, initials, the sidebar's active-page check). Screenshots: `docs/images/style-*.png` (from the earlier "Quiet utility" style; the layout is the same, the colours and type changed).

- **Tokens** are CSS custom properties: the light theme on `:root`, the dark theme on `:root[data-theme="dark"]` — the same names in both, so every rule works in either theme. Text `--ink` / `--ink-2` / `--ink-3`, one accent `--accent` (light #3D5AFE, dark #7C9CFF; hover `--accent-hover`, text on it `--on-accent`, focus ring `--accent-ring`, selection `--accent-tint`), page `--ground`, cards `--surface` (insets and hovered rows `--surface-2`) with `--line` borders, sidebar `--rail*`, floor-plan paper `--canvas` (stays light in dark so the drawing's own colours keep their contrast), status pairs (`--ok-*`, `--out-*`, `--due-*`, `--bad-*`, `--off-*`, `--fix-*`) and `--glow` (status dots glow in dark only). Type: Inter 14 px body, 24/600 page titles, 15/600 section headings, 11.5/500 column labels; JetBrains Mono for identifiers. Controls: 8 px radius, cards 10 px.
- **Theme.** The top bar has a light / system / dark switch (`[data-theme-switch]`, handled in `site.js`); the choice is kept in `localStorage` (`ats-theme`, default `system`). `wwwroot/js/theme.js` is loaded in `<head>` *without* `defer` and sets `data-theme` (and `data-rail="collapsed"` for a collapsed sidebar, `ats-rail`) before the first paint. Without JavaScript the light theme applies. The print layout never loads theme.js, so printouts are always light.
- **Top bar** (`.topbar`): the page title, the global search (IT: the same Find lookup as the overview, `[data-find-lookup]`, Enter on an exact tag jumps to its return or page; managers: a plain asset search) — Ctrl+K / Cmd+K or `/` focuses it — and the theme switch.
- **Fonts** are self-hosted (internal network, no Google Fonts): `wwwroot/fonts/` holds the latin woff2 files of Inter 400/500/600/700 and JetBrains Mono 400/500 from `@fontsource/inter@5.3.0` / `@fontsource/jetbrains-mono@5.3.0`, with both licences in `OFL.txt`. `@font-face` uses `font-display: swap`; fallback `'Segoe UI', system-ui, sans-serif`. The CSP's `font-src 'self'` covers them.
- **Classes.** Shell: `.app`, `.sidebar` (`.rail-toggle` collapses it to icons, `.nav-group`, `.nav-heading`, `.nav-link` — active via `aria-current="page"`, set in `_Layout` from the page path with `Ui.IsCurrent`), `.main-col` (`.topbar` + `.main`), `.user-card`. Page: `.page-header` (`.page-heading`, `.page-subtitle`, `.page-actions`), `.breadcrumb`, `.columns` with `.col-main`/`.col-side`/`.col-narrow`/`.col-wide`. Content: `.card` (`.card--flush` + `.card-header` for tables), `.kpis`/`.kpi` (`--overdue`, `--due`, `--accent`), `.table-wrap` (horizontal scroll inside the box) around every data table, `.kv-table`, `.dl-grid`, `.timeline` (`.timeline-marker--checked-out|available|corrected`, `.change-old` struck through → `.change-new`), `.empty-state`, `.pager`, `.link-cards`. Status: a coloured dot plus the word, `.pill pill--available|checked-out|due-today|overdue|unavailable|retired|corrected` (`Ui.Pill(...)`), small `.badge`. Messages: `.alert alert--warning|error|success|info` with an icon and `.alert-body`; `.note` for inline warnings. Buttons: `button`/`.btn` (secondary by default), `.btn--primary`, `.btn--danger`, `.btn--sm`, `.btn--block`; disabled buttons are grey. Forms: `.filters` bar, `.fields` grid of `.field` (label, control, `.hint`, `.field-error`), `.check` for checkbox labels, `fieldset`/`legend`, `.stepper` (quantity −/+), `.picker`/`.picker-option` (radio rows; selected via `:has(input:checked)`), `.action-grid`/`.action-card`, `meter.meter` for stock levels.
- **Rules.** No inline `style=""`, `<style>` or inline script (strict CSP; `tests/.../Foundation/UiStyleTests.cs` scans pages). Dynamic sizes use elements such as `<meter>`, never inline widths. A status is always a word plus colour (`Ui.Pill`), never colour alone. Mono (`.mono`) only for identifiers people read back: tags, SKUs, serials, phone numbers, IMEIs, ids. Targets are at least 44 px high (`--target`); focus is always visible (`:focus-visible` ring). Invalid fields get `aria-invalid="true"` (or the tag helpers' `input-validation-error`) and a red border. JavaScript stays progressive enhancement in `site.js` (confirm prompts, stepper buttons, the checkout item and people finders, the new-asset type reload and vendor/model filter); pages work without it. The sidebar stacks above the content below 820 px.
