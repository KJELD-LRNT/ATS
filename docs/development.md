# Development guide

## Layout

| Project | Purpose |
| --- | --- |
| `src/AssetTracker.Core` | Domain entities, `AppDbContext` (provider-agnostic), application services, access scope, audit writer, adapter interfaces (`IClock`, `IDirectorySource`, `IMailRelay`). |
| `src/AssetTracker.Infrastructure` | SQL Server registration, EF migrations, production adapters (AD `DirectorySearcher`, SMTP relay, system clock), the background jobs (`Jobs/`, hosted by the worker) and the local demo mode adapters (`Demo/`). |
| `src/AssetTracker.Web` | ASP.NET Core Razor Pages on IIS, Windows Authentication, AD-group → app-role mapping, authorization policies. |
| `src/AssetTracker.Worker` | Windows Service hosting the background jobs from `Infrastructure/Jobs` (AD sync, mail outbox sender, per-site overdue reminders, heartbeat). |
| `tests/AssetTracker.Tests` | Integration-first tests: `AppFactory` runs the real app against a real relational DB with simulated Windows principals and fake AD/relay. |

## Running locally

```bash
dotnet test                               # SQLite temp-file DB per test class
ATS_TEST_SQLSERVER="Server=...;User Id=...;Password=...;TrustServerCertificate=True" dotnet test   # real SQL Server
```

The production app requires `ConnectionStrings:AssetTracker`, `Roles:*GroupSids` and `DataProtection:KeyPath` in its config file, and `Clock:TimeZoneId` (plus the AD and mail settings) on Admin → Settings. **No production values are defaulted**: they come from Stage 0 (see issue #2).

## Conventions

- **Authorization lives in services and queries, not just pages.** Every read path goes through `AccessScope` (`VisibleAssetsAsync`, `VisiblePoolsAsync`, `VisibleLoansAsync`, `EnsureCanReadSiteAsync`). Every mutation calls `AccessScope.EnsureIt()` (or `EnsureAdmin()` for settings/grants). Page policies (`Policies.ItOnly` / `InventoryRead` / `AdminOnly`) are a second layer.
- **Audit in the same transaction.** Call `AuditWriter.Record(...)` before `SaveChangesAsync()`; never write audit in a separate save.
- **Errors.** Throw `DomainException` (400), `ConflictException` (409) or `AccessDeniedException` (rendered as 404). Pages get this mapping via `DomainExceptionFilter`.
- **Concurrency.** Never read-modify-write a pool balance. Use a conditional atomic update, e.g. `ExecuteUpdateAsync(... WHERE Available >= @q)`, and check the affected row count. A tagged asset's single open loan is enforced by the `UX_Loans_OpenAsset` unique index; translate its `DbUpdateException` into a `ConflictException`.
- **Time (WP4.2).** Store and compare instants as UTC `DateTimeOffset` via `IClock.UtcNow` (return/correction "not in the future" checks stay instant-based). `IClock` deliberately has no "local today": calendar days are per site. Use `SiteCalendar` (Core/Time): `TodayForAsync(siteId)`, `TodayForAsync(loan)` (tagged loan → the asset's **current** site, pool loan → the pool's site), `LocalTimeForAsync(siteId)`, `AllSitesAsync()` and `OverduePredicateAsync()` for queries. A site's zone is `Site.TimeZoneId` (IANA or Windows id), else the default `Clock:TimeZoneId` (`ClockOptions`, read via `IOptionsMonitor`); neither set ⇒ `InvalidOperationException`. `SiteCalendar.DefaultToday` is only for things that belong to no site (export file names). Due dates are `DateOnly` in the loan's site calendar and must be ≥ that site's today at checkout.
- **Overdue rule (D4).** `OverduePolicy` is the only definition: overdue when `siteToday >= DueDate` (from the start of the due date); `DaysOverdue = siteToday − DueDate` (0 on the due date, shown as "due today"). Reports, the loans list filter, the reports summary and reminders all use it through `SiteCalendar`. Tests: the default zone is UTC (`AppFactory`), `FakeClock.UtcToday` is every default-zone site's today; give a test site a `TimeZoneId` to test another zone.
- **Migrations.** Feature branches change the model freely; migrations are regenerated by the integrator (`dotnet ef migrations add <Name> -p src/AssetTracker.Infrastructure -s src/AssetTracker.Infrastructure -o Data/Migrations`). CI fails if the model and migrations differ.
- **Tests.** Prefer `AppFactory` integration tests (HTTP via `CreateClientAs(TestUser.X)` or services via `RunAsAsync(TestUser.X, sp => ...)`). Use fictional fixture data from `Seed`. Use unique site keys/tags per test, because each test class shares one database.
- **Service registration.** Add scoped services in `CoreServiceCollectionExtensions.AddAssetTrackerCore` and adapters in `InfrastructureServiceCollectionExtensions`.
- **Append-only ledgers.** `AppDbContext.SaveChanges*` throws `InvalidOperationException` if an `AuditEvent`, `LoanEvent` or `StockEvent` is modified or deleted through the change tracker. Never use `ExecuteUpdate`/`ExecuteDelete` on those sets (they bypass the guard). The one permitted update is linking a transfer pair: `StockEvent.CounterpartEventId` may be set once, from null.
- **Audit visibility: IT only (sponsor decision D2, `docs/decisions.md`).** `/Audit` (policy `ItOnly`) and `AuditQueryService` (`EnsureIt`) are read-only; there is no edit/delete path. Admins cannot read or alter audit by the admin role alone.

## Database-backed settings (WP4.1)

- **Where values come from.** `AppSettings` rows whose key is a configuration path in the `ActiveDirectory`, `DirectorySync`, `Mail`, `Notifications` or `Clock` section (`SettingCatalog.IsConfigKey`) are overlaid on the appsettings files by `DatabaseSettingsConfigurationProvider` (Infrastructure/Configuration), the **last** configuration source, so the database wins. Other keys (`Mail.ItMailbox`, `Worker.Heartbeat`, `Worker.Version`, and anything like `Roles:*` or `ConnectionStrings:*`) are never exposed as configuration. Options classes bind unchanged (`services.Configure<T>(config.GetSection(...))`).
- **How the provider reaches the database.** The provider is built with the configuration, before DI exists, so it never opens a connection itself. `DatabaseSettingsReloader` (singleton `ISettingsReloader`) reads the rows through a scoped `AppDbContext` — whatever the host registered: SQL Server in production, the test database under `AppFactory` — and calls `provider.Apply(rows)`, which swaps the data and fires the reload token only when something changed. Program.cs (web and worker) calls `LoadDatabaseSettingsAsync()` right after `Build()` (it also moves the source to the end if a later source was added, e.g. by `WebApplicationFactory`); `DatabaseSettingsRefreshService` reloads every `Settings:ReloadInterval` (30 s); `SettingsService` reloads after each save. A database error (unreachable, table not migrated yet) is logged once and the previous values stay; it never throws.
- **Consumers must read live values.** Singletons inject `IOptionsMonitor<T>` and read `CurrentValue` per use (`SmtpMailRelay`, `ActiveDirectorySource`, `DirectorySyncJob`, `OutboxSenderJob`, ...). For these five sections `IOptions<T>` is registered transient and resolves to the current value, so a scoped service that injects `IOptions<T>` sees changes on its next scope; a singleton that captures `IOptions<T>` would not.
- **Editing.** `SettingsService` (Core/Settings, admin only) validates a whole section (`SettingCatalog` holds keys, labels, kinds, defaults and validation; defaults must equal the options classes, pinned by `SettingsConfigurationTests.Catalog_defaults_match_the_option_class_defaults`), writes rows, audits each changed key as `setting.update` (`{before, after}`), then reloads. Empty value = remove the override. To make a new setting editable, add it to `SettingCatalog` (page and validation follow).
- **Secrets.** `Mail:Password` is stored as Data Protection ciphertext (`ISecretProtector`, purpose `AssetTracker.Settings.Secret.v1`) and exposed to configuration only as `Mail:PasswordProtected`; `SmtpMailRelay` decrypts at send time. It is write-only on the page and audited as `{secret: true, change: set|cleared}`. Web and worker share the key ring: `AddAssetTrackerDataProtection` sets the application name `AssetTracker` and persists keys to `DataProtection:KeyPath` (machine DPAPI on Windows); Testing uses an ephemeral key ring.
- **Test buttons.** *Test directory query* calls `DirectorySyncService.PreviewAsync` (same validation and safety checks as a run, no writes; audited `directory.preview`); *Send test email* calls `IMailRelay` directly (audited `mail.test`).

## Directory sync (WP1.4)

`DirectorySyncService` (Core) runs a full sync from `IDirectorySource`; the worker's `DirectorySyncJob` schedules it and admins can rerun it from `/Admin/Sync`. IT can view `/Admin/Sync` read-only (policy `ItOrAdmin`, D7); the rerun POST is admin-only (403 otherwise). A `Failed` or `Rejected` run stages one `SystemAlert` mail to the IT mailbox (`sync-alert:{runId}`, `NotificationService.QueueSystemAlertAsync`) in the same save as the run (D6). The production adapter `ActiveDirectorySource` (Infrastructure, Windows only) uses a paged `DirectorySearcher` (subtree, `PageSize` 500).

These are edited on Admin → Settings (see above).

| Setting | Default | Notes |
| --- | --- | --- |
| `DirectorySync:Interval` | none | Worker schedule (e.g. `01:00:00`), re-read at least every minute. Unset ⇒ the worker logs an error and does not sync until it is set; IT sees the stale warning. |
| `DirectorySync:MaxDropFraction` | `0.2` | **Safety check, on by default.** A run that would deactivate more than 20% of currently active people (absent or disabled) is `Rejected` and not applied. |
| `DirectorySync:MinimumExpectedCount` | `0` (off) | Absolute floor on valid entries; set from the client's directory size in Stage 0. A run with zero valid entries is always rejected. |
| `DirectorySync:StaleAfter` | `1.00:00:00` | Placeholder until the sync frequency is agreed; drives the IT stale banner and `GetStatusAsync()`. |
| `ActiveDirectory:SearchRoot` | none | LDAP path of the in-scope OU. Required. |
| `ActiveDirectory:SiteAttribute` | none | Attribute holding the designated site. Required. |
| `ActiveDirectory:Filter`, `IdAttribute`, `PageSize`, `*Attribute` | standard AD names | `objectGUID` id, `sAMAccountName`, `displayName`, `title`, `mail`, `objectSid`, `userAccountControl` (bit 0x2 = disabled; missing ⇒ treated as disabled). |

Rules: people are keyed on the directory id (rename updates the same row) and never deleted; absent or disabled ⇒ `IsActive = false`. Entries without id/username, or sharing an id or SID with another entry, are quarantined (skipped and reported; an existing person with that id is left untouched). A site value that matches no `Site.DirectoryValue` (case-insensitive) is **not** quarantined: the person is synced with no site and an `unmapped-site` issue is recorded. A failed fetch (`Failed`) or a safety-check rejection (`Rejected`) leaves the previous snapshot unchanged. Each run writes one `directory.sync` audit event.

## Operations, security headers and privacy (WP3.2)

- **Health:** `/health` (liveness, no checks) and `/health/ready` (database, directory sync, mail outbox, worker heartbeat; `Web/Health/ReadinessChecks.cs`). Both anonymous; the JSON writer emits only fixed descriptions. Thresholds: `Ops:*` (`OpsOptions`). See `docs/runbook.md` §8.
- **Worker heartbeat:** `WorkerHeartbeatJob` upserts `AppSetting` rows `Worker.Heartbeat` / `Worker.Version` (`UpdatedBy = system:worker`) every `Worker:HeartbeatInterval`; `OpsStatusService` reads them. The IT dashboard is `/Ops`.
- **Security headers:** `Web/Security/SecurityHeaders.cs` sets CSP (`script-src 'self'; style-src 'self'`, no inline), `X-Frame-Options: DENY`, `nosniff`, `Referrer-Policy: no-referrer`, and `Cache-Control: no-store` on every non-static response. **Do not add inline `<script>`, `<style>`, `style=""` or `on*=` handlers**; use `wwwroot/js/site.js` (e.g. `data-confirm="..."` on a form) and `site.css`.
- **Privacy:** `PrivacyService.AnonymizePersonAsync` (admin, audited `privacy.anonymize`) and `Person.IsAnonymized`, which `DirectorySyncService` never updates. New code that stores holder personal data in a *mutable* table must be added to the anonymization scrub; never put names/emails into append-only ledgers. See `docs/privacy-and-retention.md`.

## Asset catalog: types, custom fields, vendors, models, tag generator

Admins define what can be tracked; there is no hard-coded asset type any more (`Core/Domain/AssetType.cs`, `AssetField.cs`, `Vendor.cs`; service `Core/Catalog/CatalogService`; pages `Admin/Types`, `Admin/TypeEdit`, `Admin/Vendors`, `Admin/Models`).

- **Types** (`AssetType`, table `AssetTypes`): `Mode` is `Tagged` (individual asset with a tag) or `Pooled` (a site quantity `Pool`). A tagged type switches the standard fields of its form on or off (`UsesModel`, `UsesDescription`, `UsesSerialNumber`, `UsesCondition`); values for a field the type does not use are ignored by `AssetService`. The mode cannot change once the type has assets, pools, fields or models. Types, fields, vendors and models are never deleted, only deactivated (`IsActive`), because assets point at them. `Asset.Type`/`Pool.Type` is the entity: `ToString()` is its name, so `@asset.Type` and mail text still work, but queries must `Include` it.
- **Custom fields** (`AssetFieldDefinition`, `AssetFieldValue`): kinds `Text`, `Number`, `Date`, `Choice` (options one per line), `PhoneNumber` (E.164) and `Imei` (15 digits, Luhn). A field has `IsRequired`, `IsUnique`, `IsSensitive` (IT only) and `MaxValues` (1-5; the default Phone type has two IMEIs for dual-SIM phones). `FieldValueRules` normalizes and validates; `AssetService` stores the values in `AssetFieldValues` (position = order). A field absent from `EditAssetInput.Fields` keeps its values; present = replaced (a blank list clears it). The Edit page therefore posts every active field explicitly.
- **Uniqueness** is a filtered unique index on `AssetFieldValue.UniqueKey` (`[UniqueKey] IS NOT NULL`). The key is set for unique fields while the asset is not retired and cleared on retirement (so a number can be reused). Phone numbers and IMEIs are unique across all fields of that kind (`PhoneNumber:+31…`), other unique fields per field. Kind, uniqueness and a lower `MaxValues` cannot change once an asset has a value for the field.
- **Sensitive fields.** `AccessScope.CanSeeSensitiveFields` (IT only). `AssetService` loads, searches and reports without sensitive values for others, the details page hides the field, mail never includes them and the audit trail records `(sensitive)` instead of the value.
- **Vendors and models.** A model belongs to one vendor and one tagged type. An asset stores `VendorId` and `ModelId` (`Title` = "Vendor Model"); a model implies its vendor and must match the asset's type and vendor, and an inactive model/vendor can only stay on assets that already have it. `Description` is a separate free-text property.
- **Mail (D5)** takes the phone number from the first non-sensitive `PhoneNumber` field; reports (`InventoryAssetRow`) list the `PhoneNumber` and `Imei` field values.
- **Tag generator** (`Inventory/TagPattern`, `TagGenerator`). `AssetType.TagPattern` is a pattern such as `{SITE}D{000}OMA`: `{SITE}` is `Site.TagCode` (unique per site, set under Admin → Sites), `{000}` the counter (zeros = minimum digits), letters, digits, `-`, `_` and `.` are literal. The counter (`TagCounter`, last number per type and site) is claimed with a compare-and-set update inside the transaction that inserts the asset, so a failed create does not use a number; numbers whose tag already exists (typed by hand) are skipped. The new-asset form previews the next tag and creating with an empty tag generates it; a typed tag overrides it. A type with no pattern, or a site with no tag code when the pattern needs one, asks for a typed tag.
- **Defaults and migration.** `BuiltIn` holds the ids of the types and fields every installation starts with (Desktop, Laptop, Phone, Phone number, Peripheral, Webcam, Headset; phone number fields: provider, SIM type, SIM status, SIM number, PUC). The `AssetCatalog` migration inserts them (the ids equal the old `AssetType` enum values, so existing rows keep their type) and moves `IndividualAssets.Imei`/`PhoneNumber` into `AssetFieldValues`; `CatalogDefaults.EnsureAsync` does the same for databases created from the model (tests, demo). Keep the two in step. The migration's data conversion has not been run against a populated SQL Server by CI; try it on a copy of production data first.
- **Checkout finders.** Both fields of `Loans/Checkout` are ARIA comboboxes built by `createCombo` in `wwwroot/js/site.js`; each only enhances the plain GET form (*Find*), which keeps working without JavaScript.
  - *Who receives it?* `?handler=People&q=` (IT only, at least 2 characters, at most 8 people who can receive a loan) returns JSON with each person's site and fills the hidden `holderId`.
  - *What is being lent?* `?handler=Items&q=&type=&site=` returns assets **and** quantity pools in one list (`LendingService.SearchItemsAsync`, IT only, at most 10). The text is matched like the asset list (`AssetService.MatchingTerm`: tag, vendor/model, serial number, description, any custom field value, phone numbers/IMEIs by digits when the text looks like a number); pools by SKU, description and type name. Retired assets are never offered. Items that cannot be lent (checked out with the holder's name, unavailable, a pool with none left) are listed after those that can, greyed and not selectable; an exact tag or SKU always comes first. With an empty text it lists what is available (browse; the finder opens on focus). Picking fills `assetId`/`poolId` (disabled until picked, so without JavaScript only the text is sent); editing the text clears the pick. Picking a person sets the site filter to theirs unless the site was chosen by hand.
  - Server side (no JavaScript, or Enter on typed text): `CheckoutModel.ResolveItemAsync` takes a picked id, else an exact tag, else the text: exactly one match is selected, several are listed as links (`Matches`), none is an error. The quantity of a pool is set in the confirm step.

## Local demo mode (WP5.1)

`dotnet run --project src/AssetTracker.Web --launch-profile Demo` runs the whole app on one machine with fictional data; the user-facing guide is [`docs/testing-guide.md`](testing-guide.md).

- **Activation.** `Demo:Enabled=true` (`DemoOptions`, Infrastructure/Demo) is honoured only when `IHostEnvironment.IsDevelopment()`; in any other environment `DemoOptions.Resolve` throws at start-up. When off, nothing changes: Program.cs registers Negotiate as before and the `/Demo` pages get no route (`ConfigureDemoPages` clears their selectors, so they are 404).
- **What it swaps** (`AddDemoWeb` → `AddAssetTrackerDemo`, called after the production registrations): SQLite at `<Demo:DataDirectory>/demo.db` (`EnsureCreated()`, WAL; the migrations stay SQL Server only), `DemoClock` (real time + offset stored in the `Demo.ClockOffset` AppSetting; seeding pins it per async flow), `DemoDirectorySource` (fixed fictional directory), `PickupDirectoryMailRelay` (`.eml` files under `mail/`, read by `/Demo/Mailbox`), a plain key folder `keys/`, the background jobs hosted in the web process (`AddAssetTrackerBackgroundJobs`, shared with the worker), `DemoAuthenticationHandler` (emits Name/PrimarySid/GroupSid like Negotiate, from the `/Demo` role-switcher cookie) and `DemoCurrentUser` (seeding actor → HTTP user → `system:worker`). Demo configuration defaults (role group SIDs, short intervals, timezone) are an in-memory source added before the database settings overlay, so Admin → Settings still wins.
- **Seeding** (`DemoSeeder`) goes through the real services as an IT+admin actor, in time order with the clock pinned to past instants, so audit, ledgers and outbox are consistent; seeded mail is marked sent. It only runs on an empty database; **Reset demo data** (`DemoDataManager.ResetAsync`) empties every table and seeds again.
- **Tests:** `tests/AssetTracker.Tests/Demo/` (`DemoAppFactory` = Development + demo + temp folder, jobs off).
- Production code never references the demo types except through these Program.cs hooks, the layout's `DemoBanner` view component (renders nothing when demo is off) and the settings page note.

## UI style: "Quiet utility" (WP5.2)

One stylesheet, `src/AssetTracker.Web/wwwroot/css/site.css`; view helpers in `Pages/Shared/Ui.cs` (status pills, inline SVG icons, initials, the sidebar's active-page check). Screenshots: `docs/images/style-*.png`.

- **Tokens** are CSS custom properties on `:root`: navy sidebar `--navy-900` #14202B, text `--ink` #18212B / `--ink-2` #4A5563 / `--ink-3` #5E6876, one accent `--accent` #0B6B66 (hover `--accent-hover`, focus ring `--accent-ring`), page `--ground` #F5F6F8, cards `--surface` #FFF with `--line` #E1E4EA borders, and status pairs (`--ok-*`, `--out-*`, `--due-*`, `--bad-*`, `--off-*`, `--fix-*`). Type: IBM Plex Sans 14 px body, 26/600 page titles, 16/600 section headings, 12/600 uppercase column labels; IBM Plex Mono for identifiers. Controls: 6 px radius, cards 10 px.
- **Fonts** are self-hosted (internal network, no Google Fonts): `wwwroot/fonts/` holds the latin woff2 files of IBM Plex Sans 400/500/600/700 and Plex Mono 400/500 from `@fontsource/ibm-plex-sans@5.3.0` / `@fontsource/ibm-plex-mono@5.3.0`, with `OFL.txt`. `@font-face` uses `font-display: swap`; fallback `'Segoe UI', system-ui, sans-serif`. The CSP's `font-src 'self'` covers them.
- **Classes.** Shell: `.app`, `.sidebar` (`.nav-group`, `.nav-heading`, `.nav-link` — active via `aria-current="page"`, set in `_Layout` from the page path with `Ui.IsCurrent`), `.main`, `.user-card`. Page: `.page-header` (`.page-heading`, `.page-subtitle`, `.page-actions`), `.breadcrumb`, `.columns` with `.col-main`/`.col-side`/`.col-narrow`/`.col-wide`. Content: `.card` (`.card--flush` + `.card-header` for tables), `.kpis`/`.kpi` (`--overdue`, `--due`, `--accent`), `.table-wrap` (horizontal scroll inside the box) around every data table, `.kv-table`, `.dl-grid`, `.timeline` (`.timeline-marker--checked-out|available|corrected`, `.change-old` struck through → `.change-new`), `.empty-state`, `.pager`, `.link-cards`. Status: `.pill pill--available|checked-out|due-today|overdue|unavailable|retired|corrected` (`Ui.Pill(...)`), small `.badge`. Messages: `.alert alert--warning|error|success|info` with an icon and `.alert-body`; `.note` for inline warnings. Buttons: `button`/`.btn` (secondary by default), `.btn--primary`, `.btn--danger`, `.btn--sm`, `.btn--block`; disabled buttons are grey. Forms: `.filters` bar, `.fields` grid of `.field` (label, control, `.hint`, `.field-error`), `.check` for checkbox labels, `fieldset`/`legend`, `.stepper` (quantity −/+), `.picker`/`.picker-option` (radio rows; selected via `:has(input:checked)`), `.action-grid`/`.action-card`, `meter.meter` for stock levels.
- **Rules.** No inline `style=""`, `<style>` or inline script (strict CSP; `tests/.../Foundation/UiStyleTests.cs` scans pages). Dynamic sizes use elements such as `<meter>`, never inline widths. A status is always a word plus colour (`Ui.Pill`), never colour alone. Mono (`.mono`) only for identifiers people read back: tags, SKUs, serials, phone numbers, IMEIs, ids. Targets are at least 44 px high (`--target`); focus is always visible (`:focus-visible` ring). Invalid fields get `aria-invalid="true"` (or the tag helpers' `input-validation-error`) and a red border. JavaScript stays progressive enhancement in `site.js` (confirm prompts, stepper buttons, the checkout item and people finders, the new-asset type reload and vendor/model filter); pages work without it. The sidebar stacks above the content below 820 px.
